# 1️⃣ server.c

### Заголовки и константы

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <errno.h>
#include <sys/types.h>

#include <arpa/inet.h>
#include <fcntl.h>

#define BACKLOG 5

#define UPLOAD_DIR "uploads"
```

* Стандартные библиотеки для работы с вводом/выводом, строками, файловой системой.
* `sys/socket.h`, `netinet/in.h`, `arpa/inet.h` — работа с TCP-сокетами.
* `fcntl.h` — открытие/создание файлов.
* Константы:

  * `BACKLOG` — длина очереди входящих соединений.
  * `BUF_SIZE` — размер буфера для передачи файлов.
  * `UPLOAD_DIR` — директория для хранения загруженных файлов.

### Функция ошибки

```c
void error(const char *msg) {
    perror(msg);
    exit(1);
}
```

* Печатает сообщение об ошибке и завершает программу.
* `perror()` выводит текст ошибки, связанной с последней системной функцией.

---

### Функции для безопасной отправки/приёма всех данных

```c
ssize_t sendall(int sock, const void *buf, size_t len)
```

* Цикл отправляет **ровно `len` байт**. TCP не гарантирует, что `send()` отправит всё сразу.
* Возвращает количество отправленных байт или `-1` при ошибке.

```c
ssize_t recvall(int sock, void *buf, size_t len)
```

* Аналогично, читает ровно `len` байт.
* Полезно для файлов, когда нужно быть уверенным, что прочитали весь размер.

---

### Функция чтения одной строки

```c
ssize_t recvline(int sock, char *buf, size_t size)
```

* Читает символ за символом, пока не встретит `\n`.
* Игнорирует `\r`.
* Завершает строку нулевым символом `\0`.
* Возвращает длину строки (без `\n`) или `-1` при ошибке.
* Очень удобно для обработки текстовых команд от клиента.

---

### Создание директории для файлов

```c
void ensure_upload_dir_exists() {
    struct stat st;
    if (stat(UPLOAD_DIR, &st) != 0) {
        mkdir(UPLOAD_DIR, 0755);
    }
}
```

* Если папки `uploads` нет, создаём её.
* `stat` проверяет существование.
* `mkdir` создаёт папку с правами `rwxr-xr-x`.

---

### Обработка клиента

```c
void handle_client(int newsockfd)
```

* Основная функция работы с клиентом.
* Используется в дочернем процессе (`fork`).
* Логика:

  1. Чтение строки команды через `recvline`.
  2. Разбор команды:

     * `CALC <op> <a> <b>` → вычисляем результат.
     * `PUT <filename> <size>` → получаем файл.
     * `GET <filename>` → отправляем файл.
     * `QUIT` → закрываем соединение.
  3. Отправка ответа клиенту.
* Цикл работает до закрытия соединения.

---

#### CALC

```c
if (strcmp(cmd, "CALC") == 0) {
    double a, b;
    char op;
    sscanf(line + strlen("CALC"), " %c %lf %lf", &op, &a, &b);
    // выполняем операцию +, -, *, /
}
```

* Разбираем операцию и два числа.
* Выполняем вычисление.
* Если деление на 0 или неизвестная операция → отправляем `ERROR`.
* Иначе — `RESULT <число>`.

---

#### PUT — загрузка файла на сервер

```c
PUT <filename> <size>
```

* Сначала клиент сообщает имя и размер.
* Сервер отправляет `OK` → клиент начинает передавать `size` байт.
* Сервер пишет файл в `uploads/`.
* После окончания отправляет `OK Uploaded ...`.

---

#### GET — скачивание файла с сервера

```c
GET <filename>
```

* Сервер проверяет существование файла.
* Отправляет заголовок `SIZE <n>` или `ERROR NotFound`.
* Клиент подтверждает `OK`.
* Сервер отправляет ровно `n` байт.
* Клиент записывает в файл.

---

### main() сервера

```c
sockfd = socket(...);
bind(sockfd, ...);
listen(sockfd, BACKLOG);
```

* Создание TCP-сокета.
* Привязка к порту (`bind`).
* Прослушивание входящих соединений (`listen`).

```c
newsockfd = accept(sockfd, ...);
pid = fork();
if (pid == 0) handle_client(newsockfd);
else close(newsockfd);
```

* Для каждого клиента создаём отдельный процесс через `fork`.
* Дочерний процесс вызывает `handle_client`.
* Родительский процесс продолжает принимать новых клиентов.

### Основной цикл клиента


* Интерактивное меню:

  1. Калькулятор (`CALC`).
  2. Загрузка файла (`PUT`).

#### CALC

* Пользователь вводит операцию и два числа.
* Формируем строку:


#### PUT — загрузка файла

* Отправляем команду:

```c

```

* Ждём `OK`.
* Отправляем содержимое файла поблочно (через `sendall`).

---

#### GET — скачивание файла

* Пользователь вводит имя файла.
* Отправляем `GET filename\n`.
* Получаем ответ: `SIZE n\n` или `ERROR`.
* Подтверждаем `OK`.
* Получаем `n` байт и сохраняем в локальный файл.

---

### Отправка QUIT


* Закрываем соединение.

# 3️⃣ Важные моменты

1. **fork() на сервере** — отдельный процесс для каждого клиента.
2. **sendall / recvall** — гарантируют передачу/приём всех байт.
3. **recvline** — удобно читать текстовые команды.
4. **Передача файлов** — сначала заголовок с размером, потом ровно N байт.
5. **Калькулятор** — поддержка `+ - * /`.
6. **Безопасность** — текущий код не защищён:

   * Не проверяет символы `../` в именах файлов.
   * Не использует шифрование.
   * Не проверяет права доступа.
7. **Буферизация** — файлы передаются блоками 4 КБ, чтобы экономить память.

# 1️⃣ Подключение

```
CLIENT                     SERVER
  |                          |
  |--- connect() ----------->|  // TCP соединение
  |                          |
  |<-------------------------|  // ACK TCP
  |                          |
```

* Клиент создаёт TCP-сокет и соединяется с сервером.
* Сервер принимает соединение через `accept()` и создаёт процесс (`fork`) для работы с этим клиентом.

---

# 2️⃣ Калькулятор (CALC)

```
CLIENT                     SERVER
  |                          |
  |--- "CALC + 3 5\n" ------>|  // отправка команды и чисел
  |                          |
  |<-- "RESULT 8\n" ---------|  // сервер вычисляет и отправляет результат
  |                          |
```

**Пояснение:**

1. Клиент вводит операцию и два числа.
2. Сервер:

   * Разбирает команду (`sscanf`).
   * Вычисляет результат.
   * Формирует строку `RESULT <value>\n`.
3. Клиент выводит результат на экран.

---

# 3️⃣ Загрузка файла на сервер (PUT)

```
CLIENT                     SERVER
  |                          |
  |--- "PUT file.txt 123\n" ->|  // имя и размер файла
  |                          |
  |<-- "OK\n" ---------------|  // сервер готов принять данные
  |                          |
  |--- <123 байт данных> ---->|  // содержимое файла
  |                          |
  |<-- "OK Uploaded file.txt 123 bytes\n" |  // подтверждение успешной загрузки
  |                          |
```

**Пояснение:**

1. Клиент читает локальный файл.
2. Отправляет заголовок `PUT <filename> <size>\n`.
3. Сервер подтверждает `OK`.
4. Клиент передаёт файл блоками (через `sendall`).
5. Сервер записывает файл на диск (`uploads/<filename>`).
6. После окончания сервер сообщает `OK Uploaded ...`.

---

# 4️⃣ Скачивание файла с сервера (GET)

```
CLIENT                     SERVER
  |                          |
  |--- "GET file.txt\n" ---->|  // запрашиваем файл
  |                          |
  |<-- "SIZE 123\n" ---------|  // сервер сообщает размер
  |                          |
  |--- "OK\n" ---------------|  // клиент готов принять файл
  |                          |
  |<-- <123 байт данных> ----|  // сервер отправляет файл
  |                          |
  |--- сохранение файла -----|  // клиент пишет файл локально
  |                          |
```

**Пояснение:**

1. Клиент отправляет `GET`.
2. Сервер проверяет файл.

   * Если файл есть → `SIZE <size>\n`.
   * Если нет → `ERROR NotFound\n`.
3. Клиент подтверждает `OK`.
4. Сервер отправляет ровно `size` байт.
5. Клиент сохраняет файл на диск.

---

# 5️⃣ Завершение соединения (QUIT)

```
CLIENT                     SERVER
  |                          |
  |--- "QUIT\n" ------------>|  // клиент хочет выйти
  |                          |
  |                          |  // сервер завершает цикл handle_client()
  |                          |  // процесс дочернего клиента закрывается
  |                          |
  |--- close() --------------|  // клиент закрывает сокет
```

---

# 6️⃣ Важные детали

* **fork() на сервере**: каждый клиент работает в отдельном процессе → изоляция данных, параллельная работа.
* **sendall / recvall**: гарантируют полную передачу всех байт при отправке/приёме файлов.
* **recvline**: используется для чтения команд и текстовых сообщений (до `\n`).
* Файлы передаются **в блоках 4 КБ** (`BUF_SIZE`), чтобы не загружать всю память.
* Сервер создаёт директорию `uploads/`, если её нет.
